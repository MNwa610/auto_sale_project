# Подготовка к защите КР №2

## Карта проекта

### Запуск

| Класс | За что отвечает |
| --- | --- |
| `carmarket.Main` | Тонкий вход: вызывает `Application.launch` для JavaFX. |
| `carmarket.fx.CarMarketApplication` | Создаёт `Stage` и `Scene`, грузит `main-view.fxml` и CSS, проверяет БД при старте. |

### Controller (View)

| Класс | За что отвечает |
| --- | --- |
| `MainController` | Главное окно: таблицы, кнопки CRUD, поиск/фильтры, экспорт, открытие диалогов. |
| `RequestDialogController` | Форма добавления и редактирования заявки. |
| `CarDialogController` | Форма автомобиля: продавец, марка/модель, справочники, VIN. |
| `UserDialogController` | Форма пользователя: ФИО, логин, роль, пароль. |
| `RequestDetailsController` | Окно подробностей выбранной заявки. |
| `RelatedDataController` | Списки заявок автомобиля или автомобилей и заявок пользователя. |
| `StatisticsController` | Вкладка статистики: подписи и кнопка «Обновить». |

### Service

| Класс | За что отвечает |
| --- | --- |
| `PurchaseRequestService` | Правила заявок: дубли, SOLD/ARCHIVED, переходы статусов, поиск таблицы. |
| `CarService` | Проверки автомобиля (цена, пробег, год, VIN) и запрет удаления при заявках. |
| `UserService` | Проверки пользователя и запрет удаления при связях. |
| `CatalogService` | Загрузка справочников марок, моделей, кузова, КПП, топлива. |
| `SearchFilterService` | Общий поиск по полям и разбор диапазона цены. |
| `StatisticsService` | Расчёт показателей по спискам из Repository. |
| `SystemStatistics` | Набор уже посчитанных чисел для вкладки. |
| `DataExportService` | Превращает текущие строки таблицы в CSV или XLSX. |

### Repository и данные

| Класс | За что отвечает |
| --- | --- |
| `UserRepository` | SQL по пользователям, логину и роли (JOIN). |
| `CarRepository` | SQL по автомобилям и `car_specifications`. |
| `PurchaseRequestRepository` | SQL по заявкам, JOIN для ФИО и марки/модели. |
| `CatalogRepository` | SQL справочников. |
| `DatabaseManager` | Читает `database.properties` и отдаёт JDBC-подключение. |

### Утилиты и модели

| Класс | За что отвечает |
| --- | --- |
| `AlertHelper` | Одинаковые окна информации, ошибки, подтверждения. |
| `DialogHelper` | Открытие FXML-диалога и подписи ComboBox. |
| `TableHelper` | Заполнение колонок TableView и формат даты. |
| `CsvExporter` | Запись CSV: UTF-8 с BOM, разделитель `;`. |
| `ExcelExporter` | Запись XLSX через Apache POI. |
| `User`, `Car`, `PurchaseRequest` | Основные сущности предметной области. |
| `TableQuery` | Условия поиска, фильтра и сортировки таблицы. |
| `RequestDetails` | Заявка + пользователь + автомобиль для подробностей. |
| `ExportTable` | Заголовки и строки для экспорта. |
| `BusinessException` | Понятная ошибка правила или ввода. |
| `DatabaseException` | Ошибка JDBC; пользователю показывается общий текст. |
| `EntityNotFoundException` | Запись не найдена. |

SQL в контроллерах нет. Бизнес-правила в Service. JDBC только в Repository.

## Ответы на вопросы защиты

**Как запускается учебная система через Docker?**  
Берётся архив преподавателя, поднимается compose с PostgreSQL и backend, например `docker compose --env-file .env -f backend/docker-compose.yml up -d --wait`. Проверяются http://localhost:8080/ и `/actuator/health`. Volume не удаляем, если данные нужно сохранить. Это чужая учебная система, не наш JavaFX-клиент.

**Как запускается JavaFX?**  
`mvn javafx:run` или `carmarket.Main`. `CarMarketApplication.start` грузит `/fxml/main-view.fxml`, вешает `/css/style.css`, показывает окно и вызывает `DatabaseManager.checkConnection()`.

**Что такое Stage, Scene, Node?**  
`Stage` — окно. `Scene` — содержимое окна. `Node` — любой элемент внутри сцены: кнопка, таблица, подпись. FXML описывает дерево Node.

**Зачем FXML?**  
Чтобы разметку окна не писать длинным Java-кодом. Файл описывает структуру, контроллер — поведение.

**Как FXML связан с Controller?**  
В корне указан `fx:controller`. Поля с `@FXML` и `fx:id` связываются автоматически. `onAction="#onAddRequest"` вызывает метод контроллера.

**Как обновляется TableView?**  
Данные лежат в `ObservableList`. После чтения из Service вызывается `requests.setAll(...)`. Таблица сама перерисовывает строки.

**Зачем ObservableList?**  
Чтобы TableView следил за изменениями списка и не требовал ручной пересборки колонок после каждого обновления.

**Где бизнес-логика?**  
В `PurchaseRequestService`, `CarService`, `UserService`. Например, активный дубль заявки проверяется в `PurchaseRequestService.create`.

**Где работа с данными?**  
В `*Repository`: `PreparedStatement`, JOIN, транзакции для `cars` + `car_specifications` и `users` + `user_credentials`.

**Как обрабатываются исключения?**  
`BusinessException` — текст для пользователя через `AlertHelper`. `DatabaseException` — «Не удалось выполнить операцию с базой данных. Попробуйте ещё раз», подробности в slf4j. Пустых `catch` нет.

**Как проверяются данные?**  
До сохранения в Service: выбран ли пользователь/автомобиль, длина сообщения, цена, пробег, год, VIN, уникальный логин. Некорректное число в фильтре цены разбирает `SearchFilterService.parsePrice`.

**Как сделаны поиск и фильтрация?**  
`TableQuery` хранит условия. Service возвращает обычный `List`, контроллер кладёт его в `ObservableList`. `FilteredList` не используется. Поиск заявок идёт по ФИО, марке, модели и сообщению. Фильтры: статус и диапазон цены. Сортировка — `Comparator` в Service; клик по заголовку TableView сортирует уже показанные строки.

**Как считается статистика?**  
`StatisticsService.load` берёт `findAll` трёх репозиториев и считает количества, средние, min/max и долю `APPROVED`. Поиск главного окна на статистику не влияет.

**Как выполняется экспорт?**  
Контроллер копирует `table.getItems()`, `FileChooser` выбирает путь, `DataExportService` пишет файл через `CsvExporter` или `ExcelExporter`. Отмена диалога ничего не сохраняет.

## Сценарий демонстрации (5–7 минут)

1. Запуск `mvn javafx:run`, показать окно и вкладки. Если БД недоступна — заранее показать Alert.
2. Вкладка «Заявки»: выбрать строку, «Подробнее», затем «Добавить» / «Изменить» / «Удалить» с подтверждением.
3. «Сменить статус»: `Новая → В работе → Одобрена`, затем показать, что дальше переходов нет.
4. Поиск «Toyota», фильтр «Одобрена», цена от 500000, сортировка по пробегу, «Сбросить».
5. Вкладка «Автомобили»: добавить или изменить цену; попытка удалить авто с заявками.
6. Вкладка «Пользователи»: показать ФИО, логин, роль без пароля; связанные автомобили и заявки.
7. «Статистика» — числа, «Обновить».
8. «Экспорт» текущей таблицы в CSV и XLSX, путь через FileChooser.

## Каверзные вопросы

1. **Что будет, если PostgreSQL выключен при старте?**  
   Окно откроется, `AlertHelper` покажет ошибку БД, таблицы останутся пустыми, пока не нажмут «Обновить» при живой базе.

2. **Что будет, если нажать «Изменить» без выбранной строки?**  
   Предупреждение «Выберите заявку для изменения.» (или аналогичное для авто/пользователя). Диалог не откроется.

3. **Что будет, если подать вторую активную заявку на тот же автомобиль?**  
   `PurchaseRequestService` выбросит `BusinessException`, диалог не закроется.

4. **Что будет, если заявка на SOLD-автомобиль?**  
   Ошибка: нельзя создать заявку на автомобиль со статусом SOLD.

5. **Что будет, если из APPROVED сменить статус?**  
   `allowedStatuses` пустой, показывается, что заявка завершена.

6. **Что будет, если удалить автомобиль с заявками?**  
   `CarService.delete` заранее проверяет заявки и пишет понятный текст, а не ошибку внешнего ключа.

7. **Что будет, если в цене фильтра написать «abc»?**  
   `SearchFilterService.parsePrice` сообщает, какое поле неверно. Показанный список не затирается.

8. **Что будет, если закрыть FileChooser без файла?**  
   Экспорт не вызывается, ошибки нет.

9. **Что будет, если отфильтровать заявки и нажать «Экспорт»?**  
   Выгрузятся только строки текущей таблицы, не вся база.

10. **Что будет, если оставить пароль пустым при редактировании пользователя?**  
    Пароль не меняется. При создании пустой пароль не принимается (минимум 6 символов).
