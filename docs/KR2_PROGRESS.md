# Состояние КР №2

Работа ведётся только в существующей ветке `main`. Коммиты делает пользователь.
Каждый следующий этап начинается только по его явной команде.
По пожеланию пользователя рекомендуемые сообщения коммитов пишутся на русском языке.

- Этапы 1–3: Java 21, JavaFX 21.0.8, JDBC/PostgreSQL, главное окно и таблица заявок.
- Этапы 4–6 восстановлены по разрешению пользователя: RequestDialogController,
  request-dialog.fxml, создание/редактирование/удаление заявок, допустимые переходы
  статусов в PurchaseRequestService, проверка выбора и длины сообщения.
  AlertHelper единообразно показывает ошибки и подтверждения; DialogHelper открывает FXML-диалоги.
- Этап 7: добавлена вкладка «Автомобили», CarDialogController и car-dialog.fxml;
  CatalogService загружает справочники, модели зависят от марки, продавец выбирается из пользователей.
  CarService проверяет числа, год, справочники, VIN и связанные заявки перед удалением;
  CarRepository использует JOIN для продавца и транзакции для cars + car_specifications.
- Этап 8: добавлены вкладка «Пользователи», UserDialogController и user-dialog.fxml;
  UserService проверяет ФИО, логин, пароль и связи перед удалением; UserRepository
  получает логин/роль через JOIN и сохраняет users + user_credentials в транзакции.
  Пустой пароль при редактировании сохраняет прежний; после сохранения строка выделяется.
- Этап 9: добавлены поиск по ФИО/автомобилю/сообщению, фильтры статуса и цены заявки,
  сортировка по цене/пробегу/дате/статусу, «Применить» и «Сбросить»; у автомобилей — поиск и сортировка цены/пробега.
  SearchFilterService содержит общие правила поиска; TableQuery хранит применённые условия,
  SortField задаёт варианты сортировки. Цена и пробег заявки получаются JOIN-ом с cars.
- Этап 10: добавлены RequestDetails, RequestDetailsController и request-details.fxml
  для полной информации о заявке; RelatedDataController и related-data.fxml показывают
  заявки автомобиля, автомобили и заявки пользователя. TableHelper переиспользует настройку колонок и дат;
  Repository выполняет JOIN для связанных заявок и выборку автомобилей по seller_id.
- Этапы 11–12 не начаты. Следующий этап — статистика (этап 11), после коммита этапа 10 и команды пользователя.

## Решения

- Существующая модель Car сохранена: названия справочников преобразуются в их id внутри Repository.
  Добавлено поле sellerFullName для отображения продавца; значения справочников при сохранении не создаются.
- VIN необязателен; заполненный VIN приводится к верхнему регистру и должен содержать ровно 17 символов.
- Год: 1950 — текущий год + 1 (не выше 2100, согласно схеме).
  Цена: больше 0, максимум 9999999999,99 и два знака после запятой.
  Объём двигателя обязателен: больше 0, максимум 99,9 и один знак после запятой.
- Валидация и преобразование строковых чисел находятся в Service. Ошибка не закрывает форму.
  После сохранения таблица обновляется и сохранённая строка выделяется.
- На этапе 8 пользователь явно выбрал сохранить способ работы с паролями из КР №1:
  значение password_hash хранится и сравнивается без хеширования. Новый пароль — 6–255 символов;
  существующий короткий пароль сохраняется при пустом поле в форме редактирования.
  Пароли не выводятся в TableView и не подставляются в PasswordField.
- ФИО — до 100 символов, логин — до 50; крайние пробелы удаляются.
  Занятый логин проверяется без учёта регистра при добавлении и редактировании.
- Этап 9: Service возвращает обычный List, Controller вызывает ObservableList.setAll;
  FilteredList/SortedList не используются. PurchaseRequestService реализует Searchable<PurchaseRequest>.
  Пустой поисковый запрос означает полный список; поиск не зависит от регистра.
- Условия применяются кнопкой «Применить» или Enter в текстовом поле. Обновление и CRUD
  используют последние успешно применённые условия, а не недописанные значения полей.
  Запись, переставшая подходить под фильтр после редактирования, скрывается до сброса условий.
- Границы цены необязательны и включаются в диапазон; принимаются точка и запятая.
  «Все» в фильтре статуса соответствует null. Ошибка ввода не заменяет показанный список.
- Сортировка из списка применяется в Service через Comparator, при равенстве — по id.
  Статусы сортируются по русскому названию. Клик по заголовку TableView меняет порядок
  текущих строк; следующее «Применить» убирает сортировку заголовками и использует выбор в форме.
  «Сбросить» очищает все условия своей вкладки и возвращает порядок по id по возрастанию.
- Этап 10: кнопки «Подробнее», «Заявки на автомобиль», «Автомобили и заявки»
  открывают модальные окна только для чтения. Перед открытием запись заново читается через Service.
  getDetails собирает заявку, покупателя и автомобиль; имя продавца автомобиля получается JOIN-ом с users.
  Пароль не отображается; необязательные пустые значения в подробностях обозначаются «—».
- Связанные списки не используют фильтры главного окна и содержат в том числе завершённые заявки.
  У пользователя автомобили отбираются по cars.seller_id, а его заявки — по purchase_requests.user_id.
  Пустые списки сопровождаются пояснением и количеством записей в заголовке вкладки.
- database.sql не запускался. Файла database.properties в рабочей копии нет;
  проверка операций на реальной PostgreSQL и ручной сценарий интерфейса ещё требуются.

## Проверка

- `mvn clean compile` — успешно на JDK 21 из расширения Java в VS Code.
- `mvn test` — успешно: всего 37 тестов, 26 выполнены, 11 проверок PostgreSQL
  пропущены из-за отсутствия database.properties. Проверена загрузка всех трёх FXML
  с контроллерами и обработчиками без показа окон.
- Добавлены проверки VIN, диапазона года, числового ввода, справочников, изменения цены,
  запрета удаления автомобиля с заявками, длины сообщения и переходов статуса заявки.
- Этап 8: `mvn clean compile` и `mvn test` прошли на Java 21: всего 47 тестов,
  36 выполнены успешно, 11 проверок PostgreSQL пропущены из-за отсутствия database.properties.
  UserServiceTest проверяет CRUD и валидацию пользователей; FxmlViewTest проверяет
  загрузку четырёх FXML и пустое поле пароля при редактировании.
- Этап 9: `mvn clean compile` и `mvn test` прошли на Java 21: всего 55 тестов,
  44 выполнены успешно, 11 проверок PostgreSQL пропущены из-за отсутствия database.properties.
  TableQueryServiceTest проверяет совместную фильтрацию, поиск, диапазон цен и сортировку;
  FxmlViewTest — кнопки применения/сброса, сортировку заголовком и сохранение условий при обновлении.
- Этап 10: `mvn clean compile` и `mvn test` прошли на Java 21: всего 62 теста,
  51 выполнен успешно, 11 проверок PostgreSQL пропущены из-за отсутствия database.properties.
  RelatedDataServiceTest проверяет связи, пустые выборки и отсутствующие записи;
  FxmlViewTest проверяет шесть FXML, подробности без пароля и оба режима связанных списков.
