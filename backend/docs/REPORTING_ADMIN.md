# Аналитика, журнал аудита и пользователи

Маршруты находятся под `/api/v1`. Для всех требуется Bearer access-токен и смена временного пароля.

## Аналитика

`GET /analytics?archived=false` доступен всем ролям. По умолчанию выбираются активные автомобили, с `archived=true` — архивные. Объект `totals` содержит количество автомобилей (`count`), количество по статусам (`available`, `reserved`, `sold`), число проверенных автомобилей (`certified`), сумму (`totalPrice`) и среднюю цену (`averagePrice`, округляется до двух знаков). Для пустой выборки сумма равна 0, средняя цена — null. Массив `brands` содержит `id`, `name`, `count` по маркам и отсортирован по убыванию количества, затем по названию и ID.

## Журнал аудита

`GET /audit` доступен ADMIN. Параметры комбинируются через AND.

| Параметр | Значение |
|---|---|
| `actorLogin` | Точный логин автора из снимка события, регистр и внешние пробелы игнорируются |
| `action`, `entityType`, `entityId` | Точные совпадения |
| `from`, `to` | Включительные границы времени в формате ISO 8601, например `2026-11-21T00:00:00Z` |
| `sort` | `createdAt,desc` по умолчанию, также `createdAt,asc`, `action,asc`, `action,desc`. При равных значениях порядок определяет ID в том же направлении |
| `page`, `size` | Страница с 0, размер 1–100, по умолчанию 20 |

Ответ — страница с `content`, `page`, `size`, `totalElements`, `totalPages`. Элемент содержит `id`, `actorId`, `actorLogin`, `action`, `entityType`, `entityId`, `details`, `createdAt`. У системных событий автор отсутствует.

## Управление пользователями

Все маршруты под `/admin/users` доступны ADMIN.

| Метод и путь | Тело запроса и результат |
|---|---|
| GET /admin/users | `page` и `size` как в аудите, порядок по ID |
| POST /admin/users | `login`, `fullName`, `role`, `temporaryPassword`. Ответ 201 с созданной записью |
| PUT /admin/users/{id} | `role`, `enabled`, `version`. Ответ с обновлённой записью |
| POST /admin/users/{id}/temporary-password | `temporaryPassword`, `version`. Ответ с обновлённой записью |
| POST /admin/users/{id}/revoke-sessions | Ответ — число отозванных сессий |

Роли — VIEWER, MANAGER, ADMIN. Запись содержит `id`, `login`, `fullName`, `role`, `enabled`, `mustChangePassword`, `version`. Устаревшая версия даёт `409 VERSION_CONFLICT`. Администратор меняет свой пароль через `/auth/password`. Самостоятельная смена своей роли или блокировка через административный API возвращает `409 SELF_ADMIN_CHANGE`.

При создании и сбросе пароль сохраняется в виде BCrypt-хеша. После входа с временным паролем пользователь должен сменить его. Смена роли, блокировка, разблокировка и сброс отзывают сессии, включая действующие access-токены. Журнал изменений содержит метаданные операции.
