# Автомобили: этапы 6–9

Все маршруты требуют access-токен Bearer и смену временного пароля.
Чтение разрешено VIEWER/MANAGER/ADMIN, запись — MANAGER/ADMIN.
DELETE автомобиля и массовый DELETE доступны только ADMIN.
Единые ошибки — `application/problem+json`. Устаревшая `version` — 409.

## Поиск и пагинация

`GET /api/v1/cars` теперь возвращает объект страницы:

```json
{"content": [], "page": 0, "size": 20, "totalElements": 0, "totalPages": 0}
```

Это изменение контракта этапа 5: вместо массива используется `content`.
Параметры комбинируются через AND:

| Параметр | Правило |
|---|---|
| `q` | Подстрока внешнего кода, VIN, описания, марки или модели; до 200 символов. `%`, `_` и `!` считаются буквальными символами |
| `brandId`, `modelId`, `sellerId`, `bodyTypeId`, `transmissionId`, `fuelTypeId` | Точное совпадение положительного ID |
| `status` | AVAILABLE, RESERVED, SOLD |
| `certified` | true/false |
| `archived` | По умолчанию false; true выбирает архив |
| `tag` | Точное совпадение тега после trim/lowercase |
| `yearMin/Max`, `mileageMin/Max`, `priceMin/Max`, `engineVolumeMin/Max`, `ageMin/Max` | Включительные неотрицательные диапазоны; min <= max |
| `page`, `size` | Нумерация с 0; размер 1–100, по умолчанию 20 |
| `sort` | `price,asc`, `year,desc`, `mileage,asc`, `createdAt,desc`, `updatedAt,asc`, `externalCode,asc`; обе стороны направления допустимы для каждого поля |

Сортировка по умолчанию `createdAt,desc`. Дополнительный ключ всегда `id ASC`:
равные значения имеют стабильный порядок при неизменном наборе данных.
Возраст в фильтре и ответе одинаков: `max(0, текущий год UTC − year)`.
Будущий модельный год имеет возраст 0.

Пример: `/api/v1/cars?priceMin=100000&priceMax=2000000&certified=true&ageMax=5&sort=price,asc&page=0&size=25`.
Миграция V6 добавляет индексы архива и основных полей сортировки.

## Архив и массовые операции

- `POST /api/v1/cars/{id}/archive`, тело `{"version":0}`.
- `POST /api/v1/cars/{id}/restore`, тело с актуальной версией.
- `DELETE /api/v1/cars/{id}?version=2`, ответ 204.

Архив не меняет AVAILABLE/RESERVED/SOLD. Повторное архивирование или восстановление
с актуальной версией — без изменений и нового события аудита.
Удалять можно только архивный автомобиль; связанные заявки блокируют удаление (409).
Чтение карточки по UUID доступно и для архива. Изменение карточки и заметок в архиве запрещено.

`POST /api/v1/cars/bulk`:

```json
{"action":"ARCHIVE","items":[{"id":"11111111-1111-1111-1111-111111111111","version":0}]}
```

Действия: ARCHIVE, RESTORE, DELETE; 1–100 элементов. Ответ 200 — массив результатов
в порядке запроса: `id`, числовой HTTP `status`, `code`, обновлённый `car` или null.
Каждый элемент получает собственную транзакцию; 404/409 не откатывают соседние элементы.
Повтор UUID получает 400/DUPLICATE_ITEM. Недостаточные права на действие отклоняют
весь запрос с 403 до обработки элементов.

## Заметки

- `GET /api/v1/cars/{carId}/notes` — закреплённые сначала, затем новые; UUID разрешает равенство времени.
- `POST` на тот же маршрут: `{"content":"Проверить документы","pinned":true}`; ответ 201 и Location.
- `PUT /api/v1/cars/{carId}/notes/{id}`: content, pinned, version.
- `DELETE /api/v1/cars/{carId}/notes/{id}?version=1`, ответ 204.

Автор и время создания назначаются сервером. Ответ содержит UUID заметки и автомобиля,
ID и имя автора, content, pinned, version, createdAt и updatedAt (UTC).
Текст 1–4000 символов, после trim не пустой. Автор или ADMIN может менять/удалять
заметку; VIEWER только читает. Чужой carId возвращает 404. Устаревшая версия — 409.
Изменение увеличивает версию и обновляет время; авторство и createdAt сохраняются.
В аудит записываются тип CAR_NOTE и UUID, без текста заметки.

## CSV

### Формат и экспорт

`GET /api/v1/cars/csv/export` принимает те же фильтры и сортировку, игнорирует
page/size при выборке и экспортирует все совпадения (не более 10000).
Ответ — UTF-8, `text/csv`, вложение `cars.csv`, RFC 4180 с разделителем-запятой.
Пустой результат содержит только заголовок.

```text
externalCode,sellerId,modelId,year,mileage,price,vin,bodyTypeId,transmissionId,fuelTypeId,engineVolume,description,status,certified,tags
```

Порядок и названия колонок обязательны. Используются числовые ID справочников и
продавца, UUID не импортируется. Десятичный разделитель — точка; certified — true/false.
VIN может быть пустым. Поле tags — JSON-массив строк внутри CSV-ячейки, например
`["акция","проверен"]` (CSV экранирует внутренние кавычки). Это сохраняет теги с `|`,
кавычками и обратной косой чертой. Пустая ячейка tags равнозначна `[]`.
Свободный текст экспортируется с обратимым префиксом апострофа при риске формул Excel;
импорт этого формата снимает добавленный префикс, исходные апострофы сохраняются.
Архивный признак, version, авторы и даты не меняются через CSV.

### Проверка и применение

1. `POST /api/v1/cars/csv/preview?mode=NEW_ONLY` с `Content-Type: text/csv` и байтами UTF-8.
   BOM допустим; лимиты: 2 MiB и 2000 записей данных. Файл с неправильной структурой,
   кодировкой, заголовком или без данных получает 400; превышение байтов — 413.
2. Ответ содержит id сессии, mode, validRows, invalidRows, expiresAt и rows.
   Для каждой CSV-записи указываются line (номер логической записи с учётом заголовка),
   data, carId и error. Ошибочная строка содержит код ошибки без исходного текста.
   Проверяются Bean Validation, ссылки, бизнес-правила, уникальность кодов/VIN в БД
   и файле. Предварительные пробные изменения полностью откатываются вместе с аудитом.
3. Исправить все ошибки и отправить файл заново. `POST /api/v1/cars/csv/{id}/apply`
   применяет только полностью корректную проверку. Частичного применения CSV нет.

NEW_ONLY создаёт новые автомобили, существующий externalCode — ошибка строки.
UPDATE_BY_EXTERNAL_CODE обновляет совпавшие записи и создаёт отсутствующие.
Проверка запоминает UUID и version существующего автомобиля; apply снова проверяет
права, архив, ссылки, уникальность и версию. Любой новый конфликт откатывает весь apply.
Можно выполнить новую проверку и повторить после исправления конфликта.

Сессия принадлежит создавшему пользователю и действует 30 минут. Чужая сессия — 404;
истекшая, ошибочная или уже применённая — 409. Блокировка сессии в БД гарантирует,
что два одновременных apply дадут ровно одно успешное применение.
Успешные изменения и события IMPORTED сохраняются одной транзакцией.
